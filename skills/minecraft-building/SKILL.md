# Minecraft 建造坐标系规则

> 这个文件存在的唯一原因：**同一个错误犯了三次**（塔楼、两次鲸鱼房）。
> 每次都因为"凭记忆推导坐标"，每次都错在同一个地方。所以规则写在这里，建造前读一遍。

## 一、唯一必须记住的一条

**地板方块放 `玩家 y - 1`，不是玩家 y。**

```
玩家 y = -60        ← mc_status 报的，是脚的位置
草地方块 y = -61    ← 真正要参照的那一格
草地顶面 = -60      ← 脚踩的那一层

在 y=-60 放方块 → 占 -60..-59，顶面 -59 → 比周围高 1 格（错）
在 y=-61 放方块 → 占 -61..-60，顶面 -60 → 与周围齐平（对）
```

## 二、建造前必做的一次测量

不要心算，**读一次**：

```powershell
mc_block {x: 玩家x, y: 玩家y-1, z: 玩家z}
```

返回值就是**地面方块的 y**。后面所有建造都以它为基准：

| 想建的东西 | 方块 y |
|---|---|
| 与地面齐平的地板 | `地面方块 y` |
| 站在地板上的空间 | `地面方块 y + 1` 到 `+ 高度` |
| 屋顶 | 墙顶 + 1 |
| 门槛 | 与地板同一层 |

## 三、搭建清单（每栋建筑都过一遍）

- [ ] 量过地面方块 y 了吗？（`mc_block` 读脚下那一格）
- [ ] 地板在最下面一层，**顶面与周围地面齐平**？
- [ ] 墙体厚度算了吗？宽段的墙常常是 **2 格厚**，开门要**两层一起打穿**
- [ ] 装饰件（鳍、柱子、屋檐）会不会**压住门洞**？先规划位置再叠
- [ ] 掏空只在**宽度 ≥ 3** 的段做，否则会把整片切穿（1 格厚的壳经不起中心掏空）
- [ ] 大范围填充会不会超 4096 格？（超了就**分块**，每次 ≤ 4096）
- [ ] 建完 `mc_blocks` 抽查一个剖面，确认底面与地面同层

## 四、已验证的失败案例

| 建筑 | 错在哪 | 症状 |
|---|---|---|
| 塔楼 | 地板放在玩家 y | 整座塔垫高一格，像放在台子上 |
| 鲸鱼房 #1 | 同上 + hollow 模式连底面一起填 | 塔基高出地面，屋内比门口高一格 |
| 鲸鱼房 #2 | 同上 | 整体高 1 格，进门要上一级 |
| 鲸鱼房 #2 | 门只打穿外层（墙 2 格厚） | "哪有门"——里面有堵墙 |
| 鲸鱼房 #2 | 门开在胸鳍底下 | 打穿墙后仍被鳍挡着 |
| 鲸鱼房 #1 | 中心掏空宽度 = 身体宽度 | 尾巴和头整片被挖穿 |

## 五、尺寸与形状

- **不要用矩形盒子拼有机形状**（假山、动物）。逐层错开中心，或按曲线算每层宽度。
- 曲线收窄用 `sin(pi * i / 长度)`，比手写宽度表连续，不会出现"突然窄一格"。
- 有机形状**不能对称**：另一个小峰/小丘能救回结构感。
- 大物体的墙体多半 **2 格厚**，门、窗、通道都要按 2 格算。

## 六、坐标系速查

| 概念 | 关系 |
|---|---|
| 玩家脚位置 | `mc_status.players[].y` |
| 脚下那块方块 | 玩家 y − 1 |
| 站立层 (可放空气/可通行) | 玩家 y |
| 头部层 | 玩家 y + 1 |
| 上方两格净空 | 玩家 y + 1、y + 2 |

挖方块的"站位"判断同理：要在 `(x,y,z)` 这格站人，需要 `(x,y-1,z)` 是实心、`(x,y,z)` 和 `(x,y+1,z)` 是空气。

## 七、怀疑"没路"时

**不要用肉眼判断可达性。** 直接让它跑一次：

```
mc_player_walk {name, x, y, z}
```

返回 `(N hops, M jump(s))` 就是有路；`no route found` 才是没路。
2026-10-21 我曾断言"差 2 格跳不上去"，结果寻路器 7 跳 3 次跳跃直接上去了。

找目标点同理：先 `mc_block` 确认目标格**可站**（下面实心、本身空气），
否则会得到误导性的 `no route found`。
