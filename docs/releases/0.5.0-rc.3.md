# 0.5.0-rc.3 · 从游戏内聊天桥迁移到 Minecraft MCP

上一份公开版是 0.3.2。本次是一次破坏性接口重构：对话、模型和任务推理由外部 Agent 管理，模组负责读取世界、执行委托和返回可核验的结果。原来依赖游戏内聊天和 WebSocket 的适配器需要迁移。发布类型为 **prerelease**。

## 从 0.3.x 升级

| 0.3.x 的用法 | 0.5.0-rc.3 的用法 |
| --- | --- |
| 安装 DSH 插件、用游戏聊天向 Agent 下任务 | 在支持 MCP Streamable HTTP 的外部客户端里交谈，游戏里负责选区和人工控制。旧 DSH profile 可以保留，接入此版本无需加载它。 |
| 通过 `/agent work`、`/agent chat`、`/agent new` 或会话命令切换上下文 | 在外部客户端管理对话与会话。游戏保留 `/agent select`、`stop`、`resume`、`edit`、`config` 等工程命令。 |
| 订阅 `/ws` 获得聊天和指令事件 | 连接带 Bearer token 的 `/mcp`。旧 `/ws` 返回 404；现有自定义客户端应按 MCP 初始化流程保存服务端分配的会话 ID。 |
| 由插件决定当前操作归谁 | 多客户端可并行读取。需要独占操作时，服务端把操作权绑定到 MCP 会话。停止、换世界或租约到期后，旧计划失效；重新连接并核对世界后才能继续。 |

**安装顺序：** 先退出游戏或停服，解压完整 ZIP。在 PowerShell 7 运行 `./install.ps1 -InstancePath '<游戏目录>'` 预览，再加 `-Apply` 执行。安装器会校验清单、备份并替换同 Mod ID 的旧 JAR，保留现有配置。手动安装时应先移走旧版 JAR。然后启动世界，在外部 Agent 中配置实例地址和 token，用 `mc_status` 核对世界、玩家和选区。若要回到 0.3.2，请停服后使用安装器记录的备份恢复 JAR，旧适配器与相应版本配套使用。[安装说明](../AI-INSTALL.md) · [MCP 会话与权限](../MCP.md)

## 编辑、命令和停止

- 对区域编辑，先拿到预览和世界、计划版本标识，再应用并读回。撤销支持受管编辑；遇到后来又被改动的方块会检查冲突。大操作支持分批执行。
- `allowWrite` 与 `allowCommands` 是两个开关。前者默认关闭，后者默认开启；仅关闭直接写入仍可能允许有副作用的命令。原生命令产生的变化不自动计入编辑撤销记录。
- 玩家执行 `/agent stop` 可以中断操作。只有真人执行 `/agent resume` 才会重新开放新操作，之前的任务不会自动复活。

## 实机验收

测试使用最终发布的 JAR、Minecraft 1.21.1、NeoForge 21.1.264、Java 21。玩家选中 `x=134..137, y=110, z=145` 的四台炉子，旁边 `z=141` 另有一排健康炉。三个全新外部 DeepSeek 会话分别只收到 **「帮我看看这排炉子怎么了」**，没有坐标、故障类型或步骤提示。

| 第一次回答 | 可以复核的现场事实 |
| --- | --- |
| 第二台缺燃料 | 64 个铁矿石待烧，燃料槽空，燃烧时间与烧制进度均为 0。 |
| 第四台输出受阻 | 铁矿和煤都充足，输出槽已有 64 个铁锭；重复观察时仍未工作。 |
| 第一台上游断料 | 炉内有煤无矿，朝下的漏斗有 64 个铁矿石、状态为 `enabled=false`，旁边贴着红石块。 |

三轮实际执行的调用都在读取现场。客户端拦下了两次高亮尝试和一次用于查询方块数据的原生命令；没有执行修复。核心诊断均正确，但额外建议会出错：第一轮建议从炉顶供煤，原版熔炉应从侧面输入燃料。另一次独立测试里，Agent 用通用工具查对了 Farmer’s Delight 1.2.9 和炉灶的九宫格配方，附带的“有燃料槽”描述却是错的。[实机读数与调用摘要](0.5.0-rc.3-evidence.json)

同一 JAR 已通过单人世界的双客户端写入归属、单格预览→应用→读回→撤销、真人停止与恢复、约 120 秒写入租约过期，以及专服重启后旧会话拒绝。普通游戏聊天没有唤起任务。安装器通过 60 项回归，包含新装、升级、校验及回滚。上述结论适用于已测环境；本次没有覆盖所有第三方机器或大型多人服负载。
